## Roadmap.sh Coverage Map

This map connects the actual roadmap.sh PDFs supplied for this plan to the phases above. The roadmaps are reference maps, not a requirement to master every branch before building.

| Supplied roadmap.sh roadmap | Where it is represented in this plan | How to use it |
|---|---|---|
| JavaScript | Phases 1–2, 5–7, and parts of 8 | Core syntax first; then browser APIs, async work, modules, tooling, and practical debugging. Advanced topics such as generators, memory profiling, and framework choices can wait until needed. |
| Frontend | Phases 3–7, with UI work in 8 and 12 | Git, HTML, CSS, JavaScript, browser tools, TypeScript, build tooling, testing, accessibility, and performance. React and other frameworks come after a working browser-JS foundation. |
| Backend | Phase 8, then selected topics in 14–15 | Start with HTTP, APIs, relational data, auth concepts, tests, and deployment. Treat scaling, microservices, Kubernetes, message brokers, and advanced observability as later, project-driven topics. |
| Blockchain Developer | Phases 9–11 and 14 | Learn chain/transaction basics, Solidity, testing, contract security, wallets, contract interaction, and deployment to a local chain or testnet. Advanced scaling and specialized tools can wait. |
| AI Engineer | Phases 12–14 | Start with model APIs, prompting, structured outputs, safety, evaluation, and constrained tool use. Embeddings, vector databases, RAG, open-source models, and multimodal systems are project-dependent extensions. |
| AI Product Builder | Phases 4–8 and 12–13 | Use the product cycle: define the problem and scope, prototype, generate, refine, test with users, deploy, and iterate. The roadmap names AI builders/coding tools, but tool choice should follow the project need. |

### AI Product Builder workflow

1. **Problem definition:** State the user problem, intended outcome, smallest useful feature set, and technical constraints.
2. **Prototype:** Choose the simplest suitable tool or build approach; don't adopt a framework just because it appears on a roadmap.
3. **Generation and refinement:** Use AI-assisted coding as a helper; inspect, run, understand, and test every change you keep.
4. **Testing and feedback:** Combine your own unit/integration/E2E checks with feedback from real users when possible.
5. **Deployment:** Choose a suitable hosting/database option and configure secrets safely.
6. **Repeat:** Improve the product based on observed problems and feedback.

### Scope rule

The roadmap PDFs contain many alternatives and advanced branches. Do not turn every named technology into a required milestone. Choose one suitable option, build a project, and add other branches only when there is a concrete reason.

## Completion Rules

A phase is complete when I can:

1. Explain the core ideas in my own words.
2. Build the phase project without copying a full tutorial.
3. Test the main success path and at least a few likely failure cases.
4. Debug common errors and explain what caused them.
5. Write a README with setup, run, and test instructions.
6. Push the project to GitHub.
7. Record gaps honestly in the weekly log.

**Gap rule:** A gap stays marked `WATCH` or `UNVERIFIED` until I demonstrate it working. A gap does not automatically reopen the entire phase.

**AI tool rule:** AI can explain, review, and help debug, but I should be able to explain the code I keep and verify that it runs.

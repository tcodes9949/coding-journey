## Resources mentioned in the video

### 1. [Your Customers Hate MVPs. Make a SLC Instead.](https://longform.asmartbear.com/slc/)
- **Type:** Article / product thinking
- **Summary:** Introduces the idea of making a product **Simple, Lovable, and Complete (SLC)** rather than releasing an MVP that feels unfinished or provides too little value.
- **How I can use it:** When I build a practice app, choose one clear problem and deliver a small but complete solution. Make the core user journey work reliably before adding extra features.
- **Learning value:** Helps me practice scope control and finishing projects instead of endlessly expanding them.
- **Priority:** High when planning a project.

### 2. [Why the Best Startups Are Obsessed With Customer Feedback](https://www.getbeamer.com/blog/customer-feedback-management-startups)
- **Type:** Article / product validation
- **Summary:** Discusses how collecting and acting on customer feedback can help teams understand user needs and prioritize product improvements.
- **How I can use it:** After building a usable version of an app, ask a few people in its intended audience to try it. Record where they struggle, what they find useful, and what they expected to happen. Use that feedback to decide what to improve.
- **Learning value:** Connects coding practice to solving real user problems rather than adding features based only on my own assumptions.
- **Priority:** High after I have something usable to show.

### 3. [Mobbin — Popular iOS Apps](https://mobbin.com/discover/apps/ios/popular)
- **Type:** UI/UX design reference
- **Summary:** A library of real app screens and user flows that can be used to study interface patterns and product experiences.
- **How I can use it:** Before building an app, study two or three similar products. Look at onboarding, navigation, forms, empty states, and the main task users need to complete. Sketch my own flow before coding it.
- **Learning value:** Builds design awareness and helps me make more deliberate interface decisions.
- **Priority:** High when starting a UI-heavy project.

### 4. [roadmap.sh](https://roadmap.sh/)
- **Type:** Developer roadmaps and learning reference
- **Summary:** Provides visual roadmaps for development paths and technologies, such as frontend, backend, and full-stack development.
- **How I can use it:** Compare the relevant roadmap with my existing coding roadmap to identify possible gaps, prerequisites, and topics I may have overlooked. Treat it as a reference for discussion, not a checklist I must complete in full.
- **Learning value:** Helps me check whether my learning path is coherent and whether important fundamentals are missing.
- **Priority:** High for the upcoming roadmap review.
- **Important note:** Do not change my personal roadmap just because a topic appears on roadmap.sh. Consider my goals, current level, projects, and the skills I actually need.

### 5. [Scrimba](https://scrimba.com/s0v687325e)
- **Type:** Interactive coding lessons
- **Summary:** A learning platform with interactive coding lessons, exercises, and project-based courses.
- **How I can use it:** Check what course the saved link opens and compare it with what I am currently learning. Use it to practice a specific skill, then try to recreate a small example independently without following the lesson.
- **Learning value:** Provides structured, hands-on practice to reinforce concepts.
- **Priority:** Use when it addresses a current learning gap.
- **Important note:** The exact course or content behind this link has not yet been confirmed.

### 6. [Crusoe — Windsurf customer story](https://www.crusoe.ai/resources/customers/windsurf)
- **Type:** AI infrastructure / customer case study
- **Summary:** A case study about infrastructure used by Windsurf, an AI-powered coding product. Crusoe provides cloud and GPU computing infrastructure.
- **How I can use it:** Read for context on the infrastructure and costs that can sit behind AI software. This is background reading rather than a hands-on coding lesson.
- **Learning value:** Helps me understand some of the infrastructure ecosystem around AI applications.
- **Priority:** Low for my immediate coding fundamentals; revisit when relevant to a project or interest in AI infrastructure.

### 7. [Devin Desktop](https://devin.ai/desktop)
- **Type:** AI-assisted development tool
- **Summary:** An AI coding environment intended to help developers work on code and development tasks with an AI agent.
- **How I can use it:** If I try an AI coding agent, give it a small, clearly scoped task in a practice project. Ask it to explain its plan, review its changes, run tests, and explain unfamiliar code. I should still be able to describe and debug the result.
- **Learning value:** Can help me learn through code review and iteration, but should not replace understanding the code myself.
- **Priority:** Optional; use only if it fits my current workflow.
- **Context note:** The video may have referred to Windsurf. The saved link now points to Devin Desktop; check the current product and branding before following any tool-specific tutorial.

### 8. [Vercel Documentation — Deployments](https://vercel.com/docs/deployments)
- **Type:** Web app hosting and deployment
- **Summary:** Vercel can deploy supported web projects and integrate with Git-based workflows, including preview and production deployments.
- **How I can use it:** When I have a suitable web project, deploy it and share the live URL. Practice making a small code change, pushing it to Git, and verifying the updated deployment.
- **Learning value:** Teaches me to take a project beyond code on my computer or GitHub and make it usable by other people.
- **Priority:** High when I have a suitable web app ready to publish.
- **Link note:** My original saved Vercel URL was a login/account-error URL, so I replaced it here with the general deployment documentation.

## Suggested way to apply these resources

1. **Review my learning path:** Compare my current roadmap and goals with the relevant roadmap.sh path. Identify gaps and possible changes, but do not edit the roadmap until the comparison is reviewed.
2. **Plan one focused project:** Use the SLC article to define a small, complete outcome and Mobbin to research relevant interface patterns.
3. **Build and learn:** Use my existing learning materials first; use Scrimba if it fills a specific gap. Use AI assistance to explain, review, and debug code rather than blindly accepting generated changes.
4. **Publish when ready:** Use Vercel if it supports the project's stack and deployment needs.
5. **Get feedback:** Ask people to try the app and prioritize improvements based on what I learn.
6. **Record the evidence:** Link the project, relevant resources, and reflections in Obsidian. Record what I can now do independently, not just what I watched or read.
